# ADR 0002. 프록시 종류와 폴더 구조

- 상태: 확정
- 날짜: 2026-11-20

## 결정

1. 리버스 프록시를 구현한다. 경로 prefix 기반 라우팅 + Round-Robin. 포워드 프록시는 리팩토링 R4로 미룬다.
2. 폴더를 `server/`, `backend/`, `common/`으로 나눈다.
   - `server/`: 웹 서버 + 리버스 프록시
   - `backend/`: 테스트용 백엔드 (`/api/echo`, `/api/time`, `/api/slow`)
   - `common/`: 둘이 함께 쓰는 모듈 (net, buf, http_parser, http_response)
3. 직접 만든 클라이언트는 만들지 않는다. 테스트는 curl, 브라우저, ab, wrk로 한다. 클라이언트는 리팩토링 R2로 추가한다.

## 이유

- 리버스 프록시 하나로 명세서의 "Proxy 필수"와 "동적 요청 처리(백엔드로 전달)"를 함께 충족한다.
- 명세서의 엣지 케이스 "백엔드 응답 없음 / 타임아웃"이 리버스 프록시 기준이다.
- 백엔드를 직접 만들면 요청 → 서버 → 백엔드 전체 흐름을 우리 코드로 따라갈 수 있다. 응답에 포트를 넣어 Round-Robin 동작을 눈으로 확인한다.
- 직접 만든 클라이언트로 테스트하면, 서버와 같은 오해를 공유할 수 있어 검증이 약해진다.

## 나중에 클라이언트를 추가하기 위한 준비

- 소켓 헬퍼를 `common/net`에 두고 `net_connect()`를 포함한다.
- `http_parser`가 요청 모드와 응답 모드를 모두 지원한다. 프록시가 백엔드 응답을 해석할 때 이미 응답 모드를 쓴다.
