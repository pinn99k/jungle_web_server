# ADR 0003. 메인 · 보조 (프록시 이중화)

- 상태: 구조 확정(위임), 멈춤 판단 기준은 열림
- 날짜: 2026-11-25
- 정한 사람: 핑구가 구현을 지시하고 구조는 위임

## 배경

백엔드를 3대로 늘려도 프록시가 하나면 프록시가 죽을 때 모두 닿을 수 없다. 셸 감시자로 잰 결과(`docs/perf-baseline.md`), 죽은 메인은 쉽게 이어받지만 멈춘 메인은 포트를 쥐고 있어 이어받지 못했다.

## 결정

1. 같은 실행 파일을 둘 띄운다. 잠금 파일(`lock_file` 설정)을 얻은 쪽이 메인, 못 얻은 쪽이 보조다.
2. 잠금은 POSIX 레코드 락(`fcntl F_SETLK`)이다. 메인이 죽으면 커널이 풀어 준다.
3. 멈춤은 보조가 메인에게 HTTP 요청을 보내 판단한다(v1). 연속으로 실패하면 잠금을 쥔 프로세스를 `F_GETLK`로 찾아 SIGKILL로 끝낸 뒤 잠금을 얻는다.
4. `lock_file`이 없으면 예전과 똑같이 동작한다.

## 잃는 것

- 같은 컴퓨터에서만 통한다. 컴퓨터가 통째로 죽는 경우는 가상 IP와 두 대의 컴퓨터가 필요하다 (범위 밖)
- 보조가 멈추면 이어받을 쪽이 없다
- 메인을 끝낼 때 처리 중이던 요청은 끊긴다

## 빠뜨렸던 대안: 둘 다 일하기 (active-active, 2026-11-25 핑구 질문으로 드러남)

프록시에는 "하나여야만 하는 상태"가 거의 없다(RR 카운터는 어긋나도 됨). 그래서 컴퓨터 두 대가 동시에 손님을 받아도 되고, 그러면 누가 메인인지 · 멈췄는지 판단할 필요가 줄어든다. 메인 · 보조가 꼭 필요한 것은 하나여야 하는 것(가상 IP, 신청 중복을 기억하는 저장소)이 있을 때다. 같은 컴퓨터 안 메인 · 보조는 프로세스의 죽음 · 멈춤만 다룬다. 어느 쪽으로 갈지는 열림.
