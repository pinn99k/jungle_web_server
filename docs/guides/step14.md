# 스텝 14 읽기 가이드 — 줄 서기 (`gate`)

## 1. 추가 · 변경 파일
| 파일 | 줄 수 | 내용 |
|---|---|---|
| `server/gate.c` · `.h` | 166 · 26 | 번호표 목록, 순서, 떠남 |
| `server/proxy.c` | `gated` · `ticket_of` · `pass_gate` · `send_json` | 쿠키에서 번호표를 읽고 응답을 만듦 |
| `www/course/course.js` | 화면 | 앞에 몇 명인지 보여 주고 기다림 |
| `tests/test_gate.c` | 5개 테스트 | 순서 · 다시 눌러도 그대로 · 떠남 · 처리 중과 이미 됨 · 가짜 번호표 |

## 2. 함수 지도
| 함수 | 한 줄 설명 | 호출하는 곳 |
|---|---|---|
| `gate_visit` | 번호표로 줄에 선다. PASS · WAIT · BUSY · DONE | `pass_gate` |
| `gate_finish` | 들어갔던 일이 끝남 | `proxy_handle` |
| `join` | 새 번호표를 만들어 순서를 준다 (추첨이면 난수) | `gate_visit` |
| `count_ahead` | 앞사람을 세고 떠난 사람을 지운다 | `gate_visit` |

## 3. 손님 하나의 순서
1. 처음 오면 번호표(쿠키)를 받고 503과 "1초 뒤 다시"를 받는다
2. 같은 번호표로 다시 오면 앞사람 수를 세어, 자리가 있으면 들어간다
3. 안 오고 유예 시간이 지나면 지워진다. 자리는 다음 사람 것
4. 처리 중에 또 오면 409, 성공한 뒤면 200(이미 됨). 백엔드로 다시 가지 않는다

## 4. 왜 이렇게
- 웹서버는 **누구인지 보지 않는다.** 번호표는 추측할 수 없는 난수이고, 세션 · 토큰은 백엔드가 본다
- 기다리는 동안 연결도 워커도 쓰지 않는다. 줄이 길어도 서버가 막히지 않는다
- 여러 값을 함께 바꾸므로 락 하나를 쓴다. 프록시가 죽으면 줄도 사라진다

## 5. 실행해 볼 명령
```

./build/server -c conf/course.conf   # 화면: http://localhost:8080/course/
```
